Current state, not history. Rewrite this file at the end of any significant session.

## Project

Aether is a cellular automata laboratory: one GPU-resident engine running discrete and continuous automata on 1D, 2D and 3D lattices, with rules authored in a declarative DSL or in Lua, and with two independent mutation controls that let a run drift through rule space while it evolves. Every run is reproducible from a serialised session.

## Current state

Phases 1–6 complete (2026-09-11 to 2026-09-26), released as **0.1.0** on 2026-09-26; `aether --version` reports it. The discrete core runs interactively in 2D (square and hexagonal) and 3D (volume raymarch, orbit, clip, slice painting) with both mutation controls, a lineage log with pin and rewind, and sessions that replay bit-identically across processes. Cells can be given an ageing tail and mutation can be grouped into blocks. Rules come from the DSL or from Lua, run through either the table or the codegen backend, and nineteen of them ship in `rules/`, including three of Wolfram's elementary rules and Langton's self-reproducing loops. A continuous rule can be authored in Lua, stepped on either path, and watched: `rules/lenia.lua` holds a self-organised field at 28% of the grid over 10,000 generations at 512², where the two drivers are bitwise identical and the CPU path agrees.

## Architectural invariants

These are from ARCHITECTURE.md §Key invariants. Violating one is a defect even if the result works:

1. The IR is the only compile target. Front ends never reach past it to a backend; backends never inspect DSL text.
2. Lua runs at compile time only and is not reachable from the step loop (D-003, AV-008).
3. The step never reads the buffer it writes. The ping-pong swap lives in exactly one place (AV-004).
4. CPU and GPU paths implement identical semantics, boundary handling and cell mutation included (AV-005, AV-007).
5. All randomness comes from named seeded streams A and B (SPEC §10). No `rand()`, no `std::random_device`, no time-derived or thread-index-derived values in `sim/` or `shaders/`.
6. Rendering never mutates simulation state.
7. Rule mutation without a lineage-log append is an incomplete operation.
8. No host allocation inside the step loop on either path.

The test that matters most from Phase 1 onward is CPU/GPU equivalence. If it is red, nothing else is trustworthy — and until 2026-09-23 it could also be neither red nor green, because `[gpu]` cases were skipping at random (BUG-014). ## Known pitfalls

`ATTACK_VECTORS.md` is the canonical list. The three most likely to be hit early:

- **AV-004 (buffer aliasing).** Produces output that looks like a cellular automaton but is not the one specified. The glider-displacement test catches it; run it before trusting anything visual.
- **AV-010 (table size computed after allocation).** Compute the table size from the IR before allocating anything. A non-totalistic 3D Moore rule needs 1.3×10⁸ entries and will exhaust memory during what looks like a routine rule change.
- **AV-006 (ambient randomness).** One stray `rand()` invalidates the entire session format. Check SPEC §10 before adding any stochastic behaviour.

Build-specific:

- raylib must be built with `OPENGL_VERSION=4.3`; under the default 3.3 backend the compute entry points are silent no-ops. `cmake/Dependencies.cmake` forces this. `rlGetVersion() == RL_OPENGL_43` is the runtime assertion.
- rlgl does not wrap `glMemoryBarrier`, integer texture formats or memory-info queries. Direct GL goes through `core/gl.hpp` (raylib's glad; function pointers live in `libraylib`). Include that header, never glad directly, so direct GL use is greppable. `aether_core` exports the include path.
- raylib 6.0 renamed `rlCompileShader` → `rlLoadShader` and `rlLoadComputeShaderProgram` → `rlLoadShaderProgramCompute`. Older examples online use the old names.
- GLSL `%` on a negative operand is undefined. `lut_step.comp` normalises coordinates with non-negative arithmetic before any `%`; keep it that way when touching boundary code.
- `GL_MAX_TEXTURE_SIZE` bounds 1D textures too (32768 on NVIDIA). Tables live in SSBOs for that reason (BUG-004).
- raylib batch + custom samplers: `rlSetShader` (inside `BeginShaderMode`) flushes the batch, and every flush clears `activeTextureId[]`. Call `BeginShaderMode` *before* `rlSetUniformSampler`, or the textures registered are gone by the time the quad draws. `Renderer2D::draw` is the worked example.
- Per-step values reach the compute shader as uniforms. Do not move them back into an SSBO: a `glBufferSubData` on a buffer the previous frame still references stalls on some drivers.
- The scheduler's wall-clock budget cannot see GPU time; the frame-time feedback (`setSlowFrame`) is what keeps the UI alive under an unreachable target. `App` calls `glFinish()` before `frame(dt)` so Mesa's deferred vsync throttle is not charged to the first step.
- `TakeScreenshot` takes a path relative to raylib's base directory and quietly mangles an absolute one, so a scripted run must `cd` to where the image should land. It must also run before `EndDrawing`: after the swap the back buffer is undefined (black on Mesa).
- A run that never synchronises comes back wrong, not merely late. `GpuStepper::step` drains the queue every 64 generations and `GpuGrid::download` drains before reading back; without either, a few hundred queued dispatches produced an all-zero grid on Mesa and a corrupt one on NVIDIA (BUG-011). Barriers do not substitute — `GL_ALL_BARRIER_BITS` changes nothing. The interface never showed it because `App` calls `glFinish` once a frame for an unrelated vsync reason, so test any new batch path headlessly.
- Objects that own GL handles and are moved (`GpuStepper`, `GpuGrid`, `Renderer2D`) keep plain state in a struct copied wholesale and handles in a struct exchanged on move. Do not add a member outside those structs: a hand-listed move constructor silently drops it (BUG-007).
- GL RAII objects must be destroyed before the context is. In `App` that is structural rather than remembered: `window_` owns the context and is the class's *first* member, so everything declared below it is destroyed first (members go in reverse declaration order). Adding a GL-owning member needs no teardown entry — there is none — but it must be declared **after** `window_`, which is the whole of the rule now (IMP-010, after BUG-016 and a recurrence in F-005). Elsewhere — `tests/support`, `ui/headless` — the same discipline is a scope, not a member order.
- ImGui's default font is ProggyClean, which has no em dash (U+2014) and no bullet (U+2022) — it does have the en dash, the middle dot and the rest of Latin-1. Both missing characters are remapped onto ones it has at start-up (`AddRemapChar`, in `App::run`), so an em dash or a bullet in a rendered string is now fine and needs no thought. A character outside Latin-1 that is *not* remapped still draws as `?`, and widening the atlas's glyph range will not help, because the glyph is not in the font to be rasterised: probe with `ImFont::IsGlyphInFont` after a frame has been drawn, not at setup, where it answers false for everything (IMP-009).
- Content drawn by hand into an ImGui draw list still has to be *reserved* with a widget — `Dummy` for a block, or an `InvisibleButton` where it also takes input — or the window cannot size itself. Moving the cursor past it with `SetCursorScreenPos` instead raises an `imgui-error` every frame for every offending call, which drowns the terminal without breaking anything visible (BUG-015). If a `Dummy` or `InvisibleButton` is already there, a following `SetCursorScreenPos` is redundant as well as wrong.
- `updateCanvas` has one block of shortcuts above the `is3D()` branch and a small per-dimension block inside it. Keys and guards that are not about dimensionality belong in the shared one: it used to be two near-identical copies, and that produced BUG-018 (F1 added to one) and BUG-019 (the `swallowLeft_` clear and the `Esc` cancel hoisted into the 3D branch rather than above it, which left painting dead in 2D after any placement). The indentation there lied about the nesting in both cases — count braces rather than read whitespace.
- One mouse gesture, one handler. Placing a pattern triggers on the *press* and painting on the button being *down*, so a single click did both until `swallowLeft_` stopped it (BUG-012). Anything new on the left button needs the same thought, and the flag has to be cleared above the `WantCaptureMouse` early return or a release over a panel leaves it set.
- Every user-reachable `Simulation` mutator must journal itself. A new one that does not breaks replay silently; the `replay.*` CTest and `tests/sim/session_test.cpp` are the guard.
- The volume shader binds its samplers on texture units 6 and 7 itself; `rlSetUniformSampler` binds `GL_TEXTURE_2D` and cannot take a 3D texture. Units 0–4 are raylib's.
- Hex lattices are axial storage: a W×H grid is a rhombus on screen, `wrap` is a rhombic torus, and hex neighbourhoods are 2D only. `View2D::hexRound` and the shader's `hexRound` are twins.
- Lua is a compile-time dependency of `rule/` only, linked PRIVATE, and taken from the system rather than fetched. Nothing outside `rule/lua.cpp` includes a Lua header, and `compileLua` returns a plain IR: that is what makes AV-008 structural.
- `rot` in a signature literal derives its permutation from the neighbourhood's offsets (`rotationPermutation`), so it holds at any radius on square and hex lattices and is refused in 1D and 3D rather than guessed at.
- Generated float code is `precise`, never divides, and flushes subnormals. Every float temporary is `precise` — not only inside a growth expression, since an `f32` auxiliary field puts a float in an otherwise integer transition, so the qualifier follows the type and not the surrounding function. GLSL may contract `a*b+c` into an fma, and permits float division 2.5 ULP of error where C++ is correctly rounded; either puts the shader out of step with the oracle. A front end lowering a division computes the reciprocal on the host and emits a multiply. Equally, do not "improve" the oracle by accumulating in `double`: being more accurate than the shader is the same defect as being less (AV-015). And a value below `FLT_MIN` is flushed to zero after **every** float operation in both twins: GLSL need not support subnormals and both GPUs here flush them where C++ does not, so a decaying float expression diverged at the 120th generation (BUG-021, SPEC §6's fourth agreement rule). Do not remove the flush as a micro-optimisation; it is semantics, and it is what makes the result independent of the driver in both directions. It covers the float arithmetic the shaders do for themselves as well as generated code — the convolution's running sum, each `weight × value` term, and `self + increment` — which is what it costs the radius-13 continuous row 5.3% for. The number is written once, in `rule/glsl.hpp`, and reaches both shaders as the `AETHER_FTZ` macro `gpu_step` emits.
- A multi-field rule's GLSL has two generators, and they must agree on every name. `rule/glsl.cpp` emits the `AetherFields` struct and the functions that take it; `sim/gpu_step.cpp` emits the field images and the `aether_gather_fields`/`aether_store_fields` that fill and consume it, because image bindings are its business and not the IR's. Neither spells a shared name: both call `glslFieldsStruct`, `glslFieldSelfMember`, `glslFieldNbrMember`, `glslFieldFunction` and `glslFieldType` from `rule/glsl.hpp`, which is the only place a spelling exists. The order the stepper prepends things in matters — the struct before the code that fills it. The guard is the both-paths case in `tests/sim/fields_step_test.cpp`; a mismatch is a shader that will not link, so it fails loudly rather than silently.
- A field costs two image units and the state costs two, against a `GL_MAX_IMAGE_UNITS` that GL only guarantees to be eight. `GpuStepper::setRule` queries it and refuses, so three fields is the floor of what is portable rather than a limit anybody chose. A field's storage is an ordinary `core::GpuGrid` of the field's cell type over the same extents — a field is a grid of one value per site, and there is no second storage class for one.
- `rule/glsl.cpp` and the expression interpreter in `cpu_step.cpp` are twins, like the hash pair. Division by zero yields zero, integer arithmetic wraps at 32 bits, and the result is clamped to the state range — in both, or the backends diverge. The backend equivalence test is the guard.
- A 1D grid is not a 2D grid one cell tall. `--size 512` asks for the first and `--size 512x1` for the second, and the rule decides: an elementary rule declares `dimensions = 1` whatever the session says, and `createSimulation` takes the dimensionality from the IR rather than from the extents. A 1D run is drawn as its history (`render/spacetime`), so the canvas does not paint on it and the wheel sets pixels per generation instead of zooming.
- A rule's kind decides its index arithmetic, and there are now four table kinds. When adding one, the places that must all agree are `tableSize`, `TableLayout`, `sim::stepCell` (not `cpuStep`, which only loops), the `AETHER_KIND` branch in `lut_step.comp`, `compileLut`'s auxiliary buffer, `ir_json`, and the validator. The equivalence suite is what proves they do.
- `counted_totalistic` is the form almost every real rule wants (D-016). The DSL picks it when a rule asks about at most one state per own state; it is used only when strictly smaller, which is why binary rules keep the hashes they had.
- A rule's ageing tail is ordinary states, not a new concept: `decay` desugars in `rule/decay` and everything downstream sees a normal `outer_totalistic` IR. `metadata.decay_from` is a hint for palettes only — it is outside `ir_hash`, so a wrong value gives odd colours, never a different automaton.
- `sim/hash.hpp` and `shaders/hash.glsl` are twins. Change both or neither; `tests/sim/hash_test.cpp` compares them on the GPU.
- GL RAII objects (`GpuGrid`, `GpuStepper`, `Renderer2D`, `SpaceTime`) must be destroyed before `CloseWindow()`. Scope them inside the window's lifetime; a destructor after context teardown segfaults. In `App` the member order does this — see the pitfall above.

## Out of scope

Do not change these without asking:

- The IR schema (SPEC §4). Everything else is written against it; changes are breaking and need a DECISIONS entry.
- `LUT_MAX_ENTRIES` and the backend selection rule (D-004, SPEC §5). A tuning constant that silently changes semantics is exactly what AV-007 is about.
- The determinism contract (SPEC §11, D-006). Adding anything wall-clock-dependent or order-dependent to the step loop breaks the session format for every existing file.
- The compile-time-only Lua invariant (D-003). Reversing it needs a superseding decision, not a pragmatic exception.
- Feature scope. Items in FEATURES §Out of scope are settled: no agent-based automata, no hashlife, no distributed simulation, no lattices without integer coordinates. Hexagonal lattices are in (D-012, F-023, delivered); triangular and Penrose are candidates. Candidate features are candidates, not backlog.
- Phase ordering in ROADMAP. Building the renderer or the 3D path before the IR and the DSL means writing them twice.
