# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com). Entries reference stable IDs (`F-`, `D-`, `AV-`, `BUG-`, `IMP-`) where applicable.

## [Unreleased]

### Added
- Phase 7 begins. D-022 settles how a multi-field rule is written and which backend runs it: an expression per written field, and codegen for any rule that declares one — a table maps a finite signature to one state, and F-031 needs neither, since an `f32` field has no finite signature and such a rule writes several values at once (2026-09-27).
- The IR half of multi-field grids (F-031, step 1 of 5): `Field { name, cell_type, write }` in `RuleIR`, the `field` and `field_neighbour` operators, typing from the declared cell type, both indices bounded, hash and JSON, and `selectBackend` routing. A rule declaring no field is byte-for-byte the rule it was — the empty list contributes nothing to either — so `ir_version` stays at 1 (2026-09-27).

- The CPU oracle executes multi-field rules (F-031, step 2 of 5). `CompiledRule` carries its fields with each write expression typed once, so neither stepper infers a type; `sim/cpu_step` gathers a field at this site and at every neighbour with the state's own boundary resolution, and `cpuStep` takes a field buffer pair beside the state's. Every declared field is written every generation — a field the rule leaves alone is a copy forward, not an omission, because the buffer being written is two generations old. A `u8` field clamps to the width of its storage and an `f32` field is written as computed: SPEC §1's `[0, 1]` belongs to a continuous *state*, and a resource has no ceiling. Cell mutation stays the state's alone (AV-018) (2026-09-26).

### Changed
- `GpuStepper::setRule` refuses a rule that declares auxiliary fields, and `compileRule` refuses fields on anything but an expression transition. Both are staged refusals rather than limits: the first lifts in F-031 step 3, when the generator and the shader gain a function per written field, and the second waits on what a neighbour read means to a rule whose state is a float (D-021). A stepper that ran such a rule as though its fields were not there is AV-007 exactly, so the refusal sits where the rule cannot run (2026-09-26).

### Fixed
- The bundled Lenia rule is under test on both execution paths (F-002). The library sweep added for 0.1.0 excluded continuous rules on the grounds that `continuous_test.cpp` covered them; it did not — that file builds its own fixtures and had never loaded a bundled rule, so the one continuous rule in the library was in no equivalence test at all. It now is: every bundled `f32` rule, three boundaries, 1000 generations, with and without cell mutation, compared bitwise on both GPUs. It passes, and passed first time, so nothing was wrong — but nothing was checking either (2026-09-27).

## [0.1.0] — 2026-09-26

The first release. Phases 1 to 6 of the roadmap: the engine, both execution paths,
mutation and lineage, sessions that replay bit-identically, three dimensions,
hexagonal lattices, Lua and codegen, continuous states, and the presentation work
that made it usable rather than merely correct.

Nineteen bundled rules and nine bundled patterns, every one of them checked by
running it. Every SPEC §12 performance threshold measured and met on the target
machine, with the method and the noise floor recorded in `BENCHMARKS.md` and a
script to reproduce them.

### Added
- `--version` (`-V`): the binary reports the version it was built from. A session records its own format version but not the application's, so this was the only thing missing before a build could say what produced a run (2026-09-26).
- The equivalence suite sweeps the bundled library itself — all eighteen discrete rules, three boundaries, 1000 generations, with and without cell mutation, on both GPUs. That closes F-002's third acceptance point, which had been outstanding since Phase 1 (2026-09-26).
- `BENCHMARKS.md` and `scripts/benchmark.sh`: baselines for every SPEC §12 threshold, all met on the T1200. Rates come from the difference between two run lengths, which cancels the 100–220 ms of process start-up that would otherwise be charged to the measurement, and the 4% noise floor is stated so a difference smaller than that is not read as a change. The integrated GPU is recorded for contrast and misses the 3D target — 6 gen/s against 30 — which is worth knowing as unusable rather than slow (2026-09-25).
- `LUA.md`, a cookbook for the Lua front end: the shape of a rule, what each `kind` passes to a transition function and why you would pick it, dimensions and lattices, continuous rules and their kernels, the sandbox and its two budgets, every error message verbatim, and recipes. Every example was run, and the ones that claim to be a known automaton were proved by `compare` against their notation twin rather than asserted (2026-09-24).
- Screenshots in `docs/images/`, used by both the README and the manual: the window itself, Langton's loops, rule 90's Sierpinski triangle, Bays' 3D Life, a Lenia field, a hexagonal lattice and the pattern editor with its inspector. All captured from real runs — the Langton colony through a session replayed to generation 700, since the pattern has to be placed by hand otherwise (2026-09-23).
- `MANUAL.md`: a user-facing guide — getting started, every panel, the four rule notations and Lua, dimensions and lattices, continuous automata, the editor and its inspector, reproducibility, headless running, the screensaver, and ten worked examples. Every command in it was run and every behavioural claim checked on the oracle rather than recalled; that is what turned up BUG-017 and BUG-018, two things the documentation had been asserting and the code had never done (2026-09-23).
- Langton's loops (F-010, the last rule the library was waiting for): `rules/langtons-loops.rule` carries his 219 transitions as signature literals, reordered from his `CNESW` to Aether's canonical north, west, east, south, with `rot` supplying the other three quarter turns; `patterns/langtons-loop.rle` is the initial configuration. It compiles to a 32,768-entry table on the LUT backend. Both are transcribed data, so the test is behavioural — the loop must reproduce, and it does: two loops at generation 200, a colony by 500, looked at rather than inferred (2026-09-23).
- Screensaver mode (F-024): `--screensaver` runs fullscreen with no interface, walking a playlist of the bundled rules and reseeding each, with rule and cell mutation on some of them so a run drifts rather than repeats. The playlist is deterministic from the run's seed and draws from a PCG32 of its own rather than from stream A, so what it shows is reproducible without touching what the session says the run's randomness is. Each entry prints the command that recreates it. `--seconds` sets how long an entry lasts; any key, any mouse button or a nudge of the mouse ends it (2026-09-23).
- Three elementary rules in the library — `rule30`, `rule90`, `rule110` — the screensaver being the first thing with a reason to want them (2026-09-23).
- 1D elementary automata (F-005): `W110` in the DSL gives any of Wolfram's rules 0–255, with the eight-entry table filled through `TableLayout::indexNonTotalistic` so the front end cannot disagree with the steppers about what a neighbourhood means. The rule declares itself 1D whatever the session says, and the grid is rebuilt to match. `--size` grew a one-number form for a 1D grid (2026-09-23).
- `render/spacetime`: the space-time diagram, one generation per raster row. The history is a texture written by a GPU-to-GPU copy, so a 1D run costs no readback, and it is a ring drawn as two bands rather than scrolled by copying every row each generation. `Renderer2D::drawBand` names the row a band starts at; the palette pass is unchanged. Over the diagram the wheel sets pixels per generation. A 1D run starts from one live cell, which is the picture an elementary rule is known by (2026-09-23).
- `Simulation::frame(dt, afterStep)`: the space-time view needs every generation, not the last of each frame, and how many to step stays the scheduler's decision (2026-09-23).
- Headless frame dumps (F-022): `aether headless --png FILE` writes the final grid and `--frame-dir DIR` a numbered sequence, with `--frame-every` and `--frame-scale`; `--save` is now optional. The generation arithmetic is `ui::Recording`, the same type the window's Export section drives, and images render through the same `Renderer2D` and palette pass the window uses rather than a second host-side mapping of states to colours. A 3D dump is refused rather than guessed at. Two `frames.*` CTest cases check the sequence against the run's own final state (2026-09-23).
- Frame export (F-021): an Export section writes the viewport as a PNG, or as a numbered sequence over a generation range for something else to encode. The capture happens after the grid is drawn and before the preview and panels go over it, so what is written is the automaton rather than the interface; 3D is included, the volume render being another thing drawn into that rectangle. A recording steps by generations rather than by frames — `Recording::stepsBefore` takes over from the scheduler while one runs — so a long frame cannot drop or double a generation. `ui/capture` holds that arithmetic and is tested with no display (2026-09-23).
- The pattern preview goes through the grid's own palette pass (IMP-008): `Renderer2D::drawOverlay` draws a pattern's cells over the grid in the colours they will become, discarding anything outside the pattern and any cell it leaves empty so the grid shows through. The 4096-cell cap is gone — a 25,600-cell pattern draws in full — and a multi-state pattern now looks like what it will place. Both draws go through one `drawPass`, so the grid and its overlay cannot drift in how they map a pixel to a cell (2026-09-23).
- The cell inspector (F-030, D-018, AV-017): `sim/inspect` says what a cell is about to do and why — its state, every neighbour as the step gathered it, what the kind reduced them to, the table entry or the conditional that answered, and the state that will be written. Every figure comes out of `sim::stepCell` and its scratch; nothing about the transition is worked out a second time. Which conditional fired is read from the arena the oracle already filled rather than re-evaluated. Shown in the editor window for the cell under the cursor, with the neighbourhood drawn in its own geometry and the cells a boundary wrapped or dropped marked as such (2026-09-22).
- The pattern editor's scratch pad (F-029, D-018): `sim/scratch` is a grid and a rule of its own, stepped on the CPU path independently of the simulation, outside the session and the journal by design. It touches no GL, so its thirteen cases run with no display. A floating "Pattern editor" window draws it, paints it with the F-011 brush and steps it forward and back through a ring of previous generations; what leaves it is an ordinary pattern, placed through F-012's own path or written into `patterns/`. `E` opens it (2026-09-22).
- `rule::compileLibraryRule`: a library rule's source as an IR through whichever front end its file names. The dispatch was being done privately by each caller that needed it (2026-09-22).
- Region seeding (F-028): **Seed region** fills the shift-dragged selection at the fill densities and leaves the rest of the grid alone, with **Seed slice** doing the painting slice in 3D, where nothing drags a rectangle. `sim::fillRandomRegion` is the one implementation and the whole-grid fill is it over the whole extent, so stream A is consumed exactly as before and sessions written earlier replay unchanged (SPEC §10). The bounds travel in a `fill_region` journal event of their own (2026-09-21).
- Four more bundled patterns, completing F-027: a Brian's Brain glider, a cyclic spiral seed, a hex period-3 oscillator and a stable twelve-cell shell for 3D Life 4555. All four were found or built and then verified by running them; the hex one lives in the native format because RLE cannot say which lattice it is drawn on (2026-09-21).

Four bundled to start — glider, lightweight spaceship, Gosper glider gun and a Wireworld loop — each verified by running it rather than by recognising it, and each saying in its header whether it is transcribed or constructed (2026-09-21).

### Fixed
- Placing a pattern in 2D no longer kills painting for the rest of the session (BUG-019). BUG-012's `swallowLeft_` clear had been put inside the `is3D()` branch rather than above it, so in two dimensions — the only place patterns can be placed — the flag was set on the first placement and never cleared. `Esc` was stranded the same way and never cancelled a pending pattern. Live since 2026-09-21 (2026-09-23).
- `F1` and `?` open the Keys section in two dimensions as well as three (BUG-018). Fixed by removing the duplication rather than adding the missing line to it: `updateCanvas` kept two near-identical keyboard blocks and the thirteen shortcuts common to both are now written once, above the branch. That duplication produced both this and BUG-019 (2026-09-23).
- `--rule @name` resolves in `aether headless` as it does in the window (BUG-017), so a scripted run can name a bundled rule — Lua ones included. The search path is now `ui::ruleSearchPath()` rather than a list written inline in `App::run`, because a second copy of it in `headless.cpp` would have been a fresh way for the two to disagree. The rule also decides the dimensionality here, announced rather than silently applied. Guarded by comparison: the same rule named and spelled out must produce identical sessions (2026-09-23).
- `[gpu]` cases no longer skip at random (BUG-014). GLX stops returning framebuffer configs after a few dozen window init/teardown cycles, so a hidden window per case meant a growing share of the GPU suite silently did not run while the suite reported success. One context now serves the whole run: 51 of 51 cases and an identical assertion count on every run, where the count had varied between 3,943 and 5,154, and about fifteen seconds off the suite. `requireGl` also now distinguishes no display, which skips, from a display where the context will not come up, which fails (2026-09-23).
- Em dashes and bullets render instead of question marks (IMP-009). ImGui's default font has neither glyph, so both are remapped at start-up onto characters it does have — an en dash and a middle dot — which fixes every existing string and every future one, where widening the atlas's glyph range would have fixed none of them (2026-09-23).

### Changed
- SPEC §12 points at `BENCHMARKS.md` for baselines rather than carrying figures of its own, and its cell-mutation note is corrected: at `p = 0` the cost is nothing rather than little, since a zero threshold makes both steppers skip the branch, and at `p = 0.02` it is 15% of the rate rather than the ~10% recorded in Phase 2 (2026-09-25).
- `App` owns the GL context as its first member, so every GL-owning member below it is destroyed while the context is still open (IMP-010). The teardown list in `run()` is gone rather than centralised: there is no longer a list to forget to add to, which is what let the same crash happen twice (BUG-016, and again in F-005). Proved by adding a GL member with no teardown at all — safe below `window_`, a segfault above it (2026-09-23).

It joins the candidate features together with the multi-kernel generalisation that would carry it, and with the note that its sigmoids would additionally want `exp` (2026-09-19).
